# 前端开发过程与范围记录

日期：2026-11-08。记录实际工作阶段，不将它伪造成历史 Git 提交或已上线能力。

## 1. 产品范围调整

从旧运动解救玩法调整为瑜伽写真创作，排除游戏、伙伴、奖励、积分和虚拟角色。明确首页、轻量练习、拍照选片、生成与保存主流程。

## 2. 视觉方向与可用性修正

早期参考摄影画廊与瑜伽风格。根据反馈，功能界面增加常驻导航、卡片、按钮和边框，收敛杂志式排版。整体灰白黑，摄影保留自然肤色。练习与取景改为无留边全屏。

## 3. Framer 设计迭代

处理首页侧栏、替换晨光图片、手机首页布局、全屏构图、取景控件位置及静音倒计时状态。Framer 并未全部收尾，部分手机页面和异常状态仍待整理。

## 4. 时间受限的前端演示

用户确认优先交付可运行的前端演示后，建立 React / TypeScript / Vite 工程，使用已确认素材实现页面与状态，不调用付费 API。引入真实的前端计时、选片、大图和文件下载，生成与检测明确模拟。

## 5. 浏览器验收

实际验证主流程、选片跨页保留、失败重试、离开确认、刷新恢复选择与下载文件；检查 320 / 390 / 768 / 1440 px 的主要页面布局。原始记录与数据在 verification 中。

## 6. 离线交接整理

管理者无法访问 GitHub，因此改为 ZIP 交付：完整源码、已构建静态成品、文档、Nginx 示例与无依赖预览工具。资源改用构建基路径，支持部署到根目录或网站子目录。附 PR 说明，便于管理者导入自己的代码管理平台。

## 后续

离线交付后，用户另行要求同步 GitHub。增加 GitHub Actions 的构建检查与 Pages 部署，并通过 PR 提交完整前端和文档。原离线 ZIP 保持独立可用。

真实摄像头和端侧检测由前端接入；后端提供上传、生成任务与结果接口。接口草案需双方确认，完成联调、真机验证与上线验收后才能称为真实产品。
