## 先确认产品范围

本次交付可以直接部署并演示，但不等于具备真实摄像头 / 检测 / 图生图能力。页面提示明确区分模拟和真实结果。

## 部署关系

建议同一域名分流：`https://<域名>/` 提供前端静态文件，`https://<域名>/api/v1/` 反向代理后端。前端静态资源与后端应用可以在同一服务器，也可以由 Nginx 代理到不同机器。

当前前端没有 `/api` 请求，也没有已经生效的 `API_BASE_URL` 配置。接口确认后，前端需要新增真实 provider，替换 `App.tsx` 中的模拟计时 / 静态 photo 列表。单纯部署到同一个域名不会自动连接。

## 建议接口

详细请求、响应和错误约定见 [API_CONTRACT.md](API_CONTRACT.md)。这是联调提议，不是已经实现或经后端确认的接口。

1. 创建短期匿名会话（如果选择此鉴权方式）。
2. 上传用户确认的单张照片，返回 `photoId`。
3. 创建生成任务，携带幂等键，返回 `jobId`。
4. 查询任务状态，真实状态为排队 / 运行 / 成功 / 失败 / 取消。
5. 下载成功结果；处理有效期和不存在情况。
6. 取消任务 / 删除原图，策略由双方确认。

## 联调顺序与验收

| 步骤 | 后端需提供 | 验收结果 |
| --- | --- | --- |
| 1. 接口确认 | 字段、鉴权、错误码、限额、测试环境地址 | 文档明确哪些提议接受 / 修改，不靠口头假设 |
| 2. 上传 | 有效图片、超限、损坏图片、无权限样例 | 前端显示成功 / 失败；只有确认后的照片上传 |
| 3. 创建任务 | 幂等响应、限流、超时样例 | 双击或网络重试不会创建重复计费任务 |
| 4. 状态查询 | queued / running / succeeded / failed 响应 | 状态与界面一致，无真实进度就不显示百分比 |
| 5. 结果与下载 | HTTPS 结果地址、下载响应、过期响应 | 预览、放大、保存均为同一个任务的真实结果 |
| 6. 中断与恢复 | 取消语义、任务恢复规则、原图有效期 | 离开后的实际行为和提示文案一致 |
| 7. 异常回归 | 429、鉴权失效、5xx、取消、网络中断 | 不白屏，不把原图冒充真实生成成功 |

## 后端需回答的事项

- 使用哪个图生图服务？模型输入 / 输出格式、耗时、费用与内容限制是什么？
- 首版鉴权采用匿名会话还是现有账号？是否复用管理者的认证系统？
- 后端接口前缀与服务端口是什么？是否采用同域 `/api/v1/`？
- 原图 / 结果图存哪里、保留多久、是否支持删除与任务取消？
- 图片格式、大小、像素限制，以及任务并发和频率限制是多少？
- 下载通过后端代理还是对象存储 URL？跨域读取与 URL 失效如何处理？
- 超时重试是否可能重复计费？是否支持幂等和任务恢复？

这些问题尚无已确认答案。本包不包含生产域名、服务器密码、模型密钥或真实用户照片。

## 实现注意点

- 模型服务密钥由服务端管理，不放在前端 `VITE_*`、源码、浏览器存储或 ZIP 中。
- 端侧判断可以改善体验，但上传的尺寸、格式、权限与配额仍需服务端验证。
- 任务、原图、结果必须绑定当前授权主体；知道 ID 不等于有权限读取。
- 用户视频不需要上传；首版仅在用户选片确认后上传一张图片。
- 使用 HTTPS；真实摄像头权限是浏览器前端工作，部署后由用户主动授权。
- 日志记录 requestId / jobId / 耗时 / 错误码，不记录原图内容和令牌。

## 交付回执建议

管理者确认：静态演示能打开、手机能访问、示例下载成功、已理解模拟边界。后端确认：接口草案已阅读，给出修改版与可用测试环境。前端收到接口后再进入真实功能联调。
